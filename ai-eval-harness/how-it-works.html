Bounded Cost by Design

Two separate budget envelopes. Every LLM-call pathway bounded by batch size or daily cap. Verdict-bearing evaluation is never the place to economise.

📡 B_continuous — L1-b Online Evaluators

Runs 24/7 against production traffic. Controlled by daily caps per use case, not monthly batch formulas.

  • Uses a cheap model (L1B_JUDGE_LLM) — not the calibrated verdict judge
  • Regulated: 500 traces/day cap
  • Critical: 200 traces/day cap
  • Standard: 50 traces/day cap
  • Error + guardrail traces: always covered, outside cap

🔬 B_batch — L2/L3 Harness Batches

Per-run spend on verdict-bearing evaluation. Formula:

N = B_monthly / (c_L2 × 1.2 × f_runs)
1.2 = repeatability overhead

  • CI/CD gate batches: always full coverage
  • Regression batches: parameterized by budget
  • Empirical c_L2 available after 30 days via key metering

✂️ Cost Reduction Policies

  • DeepEval: 10–20% subsample; full batch only if RAGAS divergence > 0.15
  • Self-consistency: 100% on CI/CD gate; 25% on regression batches
  • Tracked-only metrics: 20% subsample for trend analysis
  • L1-a: zero cost — no LLM calls ever
What must never be cut: Repeatability checker · Sample floors (50 L2-only / 100 L3) · 100% error + guardrail trace coverage · CI/CD gate batches (no sampling) · Judge calibration (50 items, quarterly)

Judge Governance

Automated evaluation is only as trustworthy as the judge model behind it. Four conditions must hold on every evaluation run.

🚫

Different Model Family

The judge must be from a different provider or family than the system under test. Enforced at config level — not policy.

📋

On Approved List

Judge model must be on the platform-maintained approved-for-evaluation list. Unapproved models are rejected at harness startup.

📌

Version-Pinned

The exact model version is recorded in every evidence record. A version change triggers re-calibration before the next run.

✅

Calibrated Before Use

One manual calibration run against a 50-item human-labeled sample. Agreement rate ≥ 0.85 required. Quarterly re-calibration in Phase 3.

Two judge models, two roles: PINNED_JUDGE_LLM — calibrated, verdict-bearing, used for L2/L3 only.   L1B_JUDGE_LLM — cheap model, L1-b online evaluators only, never gates a verdict. The judge model is never overridable by callers — it is a server-side configuration value only.

Three Design Guarantees

These are the structural properties that make the framework defensible — not aspirational goals, but enforced invariants.

GUARANTEE 01

Responsible by Design, Not by Audit

The three non-overridable NO-GO conditions — safety violation, critical test case failure, GT dataset invalidated — cannot be bypassed by anyone, including product owners. They are enforced in code. The framework catches problems before production, not after.

GUARANTEE 02

Evidence Over Assertion

Every verdict is an immutable, content-hashed record. The hash detects any post-hoc modification. The GT trust tier system ensures reference answers came from source documents, not from the same model family being evaluated. A score without a trail is not a verdict.

GUARANTEE 03

Circular Evaluation is Structurally Impossible

The evaluation target, the verdict judge, and the GT generator must all be from different model families — enforced at config level. GT items generated by the same family as the evaluation target are classified Rejected and blocked at upload. The verdict cannot prove itself.
